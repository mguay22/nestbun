NestJS on Bun, natively.

An HTTP adapter that runs your Nest app straight on Bun.serve(). Swap one line, keep every controller, pipe, guard and filter, and drop the build step.

Get started View source 
// bun add @nestbun/platform
import { NestFactory } from '@nestjs/core';
import { BunAdapter, type NestBunApplication } from '@nestbun/platform';

const app = await NestFactory.create<NestBunApplication>(
  AppModule,
  new BunAdapter(),
);
await app.listen(3000);

// bun src/main.ts   ← no nest build, no dist/

Why not just run Express on Bun?

You can, and it works. But you are paying for a Node compatibility layer on every request. Going straight to Bun's native server removes it, and unlocks Web-standard primitives along the way.

Faster than Express and Fastify

Same app, same runtime, same machine: the Bun adapter serves more requests per second than either, on both JSON reads and JSON writes.

Web standards underneath

Requests are Web Requests, responses become Web Responses, files stream with zero-copy Bun.file(). Express-shaped req/res shims keep the ecosystem working.

Tests without sockets

adapter.fetch(new Request(...)) runs a request through the full Nest pipeline in-process. No supertest, no port, no flakiness.

What works today

Every feature is covered by an integration test that boots a real Nest application on the adapter and talks to it over HTTP.

  • Routing, params, wildcards, HEAD → GET fallback
  • @Body / @Query / @Param / @Headers / @Ip / @Req / @Res / @Next
  • JSON + urlencoded parsing, rawBody, size limits
  • Exception filters with Express-identical 404 / 500 shapes
  • MiddlewareConsumer, app.use(), next(err)
  • Global prefix, URI / header / media-type versioning
  • CORS, cookies, @Redirect, @Header, @HttpCode
  • Server-Sent Events with disconnect detection
  • StreamableFile and manual res.write() streaming
  • Static assets with ETag / 304, view engines (ejs, hbs, pug)
  • @nestjs/swagger, @nestjs/testing
  • HTTPS, graceful shutdown, unix sockets
  • WebSocket gateways (@nestbun/ws)
  • Multipart uploads (@UploadedFile)

Install

bun add @nestbun/platform @nestjs/common @nestjs/core reflect-metadata rxjs

Requires Bun ≥ 1.3 and NestJS ≥ 12. Remove @nestjs/platform-express from your dependencies; nothing else in your app changes.

Options

new BunAdapter({
  trustProxy: true,          // honor X-Forwarded-For / -Proto / -Host
  bodyLimit: '1mb',          // default 100kb, same as Express
  serve: {                   // forwarded to Bun.serve()
    idleTimeout: 120,        // seconds, max 255
    maxRequestBodySize: 128 * 1024 * 1024,
    shutdownTimeout: 10_000, // ms to drain in-flight requests on app.close()
  },
});

Typed application

const app = await NestFactory.create<NestBunApplication>(AppModule, new BunAdapter());
app.useStaticAssets('public', { prefix: '/static', maxAge: '1d' });
app.setViewEngine('ejs');      // or 'hbs', 'pug', or { render(file, data) }
app.useBodyParser('text');     // alongside the default json + urlencoded

Tests without a port

const adapter = new BunAdapter();
const app = moduleRef.createNestApplication(adapter);
await app.init();

const res = await adapter.fetch(new Request('http://localhost/users/1'));
expect(res.status).toBe(200);

Differences from Express you may notice

  • Query strings use Express 5's simple parser: repeated keys become arrays, no a[b]=c nesting.
  • Routes match in declaration order (first match wins), exactly like Express. Declare :id routes after static siblings.
  • Buffer return values are sent as raw bytes rather than JSON-encoded.
  • Express middleware works when it only touches req.headers/body/query and res.setHeader/status/end/json. Sub-routers and req.url rewriting do not.
  • supertest needs a Node http.Server; use adapter.fetch() instead.

How it works

BunAdapter extends Nest's AbstractHttpAdapter. Each request is wrapped in a BunRequest (Express-shaped, lazily computed fields, the Web Request exposed as native) and a BunResponse that implements the node:stream Writable interface, natively in Bun, and resolves into a Web Response. That is what lets Nest's own SSE stream and StreamableFile pipe into it unchanged. A small Express-style router on path-to-regexp v8 runs middleware and routes in order.
